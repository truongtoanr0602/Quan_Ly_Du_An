API CONTRACT CẦN XÁC NHẬN
- Endpoint và HTTP method.
- Request DTO cho Create/Update.
- Response DTO cho List/Detail.
- Kiểu dữ liệu của Id và CreatedAt.
- Cấu trúc validation errors.
- Cấu trúc lỗi 401, 403, 404 và 409.
- Cách gửi JWT.
- Base URL qua biến môi trường.
- Cách Frontend xử lý danh sách rỗng.

Nếu Backend và Frontend đang dùng contract khác nhau:
1. Ghi rõ khác biệt.
2. Xác định tài liệu hoặc Acceptance Criteria làm căn cứ.
3. Đề xuất phương án thay đổi nhỏ nhất.
4. Xin xác nhận trước khi sửa public API.

LUỒNG TÍCH HỢP ƯU TIÊN
Admin/Customer mở trang Category
→ React gọi GET /api/categories
→ ASP.NET Core Controller nhận request
→ Service xử lý
→ EF Core truy cập SQL Server
→ API trả response
→ React hiển thị dữ liệu hoặc trạng thái lỗi.

LUỒNG QUẢN TRỊ CẦN KIỂM TRA
- Chưa đăng nhập gọi POST/PUT/DELETE nhận 401.
- Customer gọi POST/PUT/DELETE nhận 403.
- Admin tạo hoặc sửa Category hợp lệ thành công.
- Tên bị trùng nhận 409 và UI hiển thị thông báo.
- Xóa Category đang có Product nhận 409 và UI hiển thị thông báo.

NHIỆM VỤ REVIEW
Khi review Backend:
- Controller có chỉ xử lý HTTP hay chứa business logic?
- Service có áp dụng đúng quy tắc US-2?
- Entity/DTO có bị lẫn trách nhiệm?
- Migration và unique constraint có phù hợp?
- Mã lỗi HTTP có đúng?
- Test có bao phủ trường hợp quan trọng?

Khi review Frontend:
- TypeScript types có khớp DTO?
- API client có dùng base URL từ môi trường?
- Có xử lý loading, empty và error?
- Có hiển thị lỗi 401/403/409 đúng ngữ cảnh?
- Có kiểm tra quyền Admin?
- Test UI có kiểm tra hành vi thay vì chi tiết triển khai?
