# Technical Baseline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a shared, runnable technical baseline for the e-commerce MVP without implementing any Sprint 1 business User Story.

**Architecture:** Use a single ASP.NET Core Web API project plus a test project, a separate React/TypeScript/Vite application, and SQL Server through EF Core. Repository-wide `AGENTS.md` routes agents to focused, version-controlled project skills and canonical documents.

**Tech Stack:** .NET 10 LTS, ASP.NET Core Web API, EF Core, SQL Server, JWT, Swagger/OpenAPI, React, TypeScript, Vite, Node.js 24 LTS, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-21-technical-baseline-design.md`

## Global Constraints

- Read `docs/architecture.md`, `docs/Sprint_backlog.md`, and `docs/Sprint1.md` before changing the baseline.
- Do not implement Sprint 1 business endpoints, domain entities, migrations, or UI screens.
- Do not introduce Clean Architecture, microservices, Docker, an external UI framework, or an unapproved dependency.
- Frontend communicates with backend only through REST API.
- Business logic belongs in the Service Layer; persistence uses EF Core and SQL Server.
- Authentication is JWT-based and recognizes `Admin` and `Customer` roles when its Sprint task is implemented.
- Secrets must not be committed.
- Preserve all pre-existing user files and changes.
